Lesson 06 · старт пары

Типовые ошибки и эквивалентные формы SQL-запросов

Эта страница нужна для первого блока занятия. Её задача — быстро выровнять язык SQL после лабораторной работы: понять, какие формы записи действительно эквивалентны, а какие меняют смысл запроса или делают его менее надёжным.

Что здесь важно вынести

На этом шаге мы не ищем «единственный правильный стиль». Мы договариваемся о том, какие формы записи допустимы, какие конструкции полезно писать явно, а где ошибка уже меняет смысл ответа.

1. JOIN и INNER JOIN

Эквивалентно
SELECT ...
FROM flights f
JOIN airports_data a
  ON f.departure_airport = a.airport_code;
SELECT ...
FROM flights f
INNER JOIN airports_data a
  ON f.departure_airport = a.airport_code;

Обе записи означают одно и то же: взять только совпавшие строки из двух таблиц. Полная форма INNER JOIN просто делает смысл соединения явным.

2. Когда нужен LEFT JOIN

По смыслу задачи
SELECT a.airport_code, f.flight_id
FROM airports_data a
LEFT JOIN flights f
  ON a.airport_code = f.departure_airport;

LEFT JOIN выбирают тогда, когда важно сохранить все строки из левой таблицы, даже если справа для части строк пары нет.

Если вы хотите «сохранить все аэропорты, даже если вылетов не было», то без LEFT JOIN такую задачу не решить.

3. RIGHT JOIN и FULL JOIN

Важно понимать

RIGHT JOIN полезно уметь читать, но на практике его часто проще переписать через LEFT JOIN, просто поменяв таблицы местами.

FULL JOIN нужен реже: он сохраняет обе стороны даже без совпадений. Это полезная идея, но её стоит применять только тогда, когда задача действительно требует «объединить всё с обеих сторон».

4. Сортировка по умолчанию

Эквивалентно
ORDER BY total_amount
ORDER BY total_amount ASC

По умолчанию ORDER BY уже означает сортировку по возрастанию. Поэтому ASC можно не писать. Явно чаще указывают именно DESC, если нужен обратный порядок.

5. Несколько способов задать условие

Эквивалентно
WHERE city IN ('Москва', 'Санкт-Петербург')
WHERE city = 'Москва'
   OR city = 'Санкт-Петербург'

Обе записи допустимы. Вариант через IN обычно короче и лучше читается, когда речь идёт о наборе конкретных значений.

Если в условии смешиваются AND и OR, не экономьте на скобках: они помогают не потерять смысл запроса.

6. Проверка пустых значений

Неэквивалентно
WHERE actual_arrival = NULL
Правильно
WHERE actual_arrival IS NULL

Сравнение с NULL через знак равенства не работает так, как обычное сравнение. Для пустых значений используются формы IS NULL и IS NOT NULL.

7. Алиасы и AS

Эквивалентно
SELECT COUNT(*) AS flights_count
FROM flights f
SELECT COUNT(*) flights_count
FROM flights f

Обе записи допустимы, но явное AS делает запрос прозрачнее, особенно в длинных агрегационных задачах.

8. Мини-вопрос

Какой тип соединения нужен, если требуется сохранить все аэропорты, даже когда в рассматриваемый период из части из них не было вылетов?

Нужен LEFT JOIN, если таблица аэропортов стоит слева.
