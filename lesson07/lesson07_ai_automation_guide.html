1. Конструктор ИИ-автоматизации

Любую автоматизацию удобно проектировать как ответ на пять вопросов. Если студент может ответить на эти вопросы, он уже понимает архитектуру своего прототипа.

1. Откуда берутся данные?

Форма, таблица, CSV-файл, CRM, заявка, опрос, письмо, сообщение, выгрузка с сайта.

2. Что запускает процесс?

Отправка формы, появление новой строки, ручной запуск, новое письмо, новый файл, webhook.

3. Кто передаёт данные дальше?

Albato, Make, n8n, Google Apps Script, Python-скрипт, другой интегратор или собственный код.

4. Какой ИИ обрабатывает данные?

GigaChat, YandexGPT, Qwen, DeepSeek, локальная модель через Ollama или другой доступный API.

5. Куда попадает результат?

Email, новая строка в таблице, сообщение, карточка заявки, отчёт, PDF/HTML, комментарий в CRM.

6. Как проверить результат?

Проверить исходные данные, формулы, пропуски, числовые основания и ограничения ИИ-вывода.

На занятии подробно разбирается один готовый вариант. В домашней работе можно повторить его или собрать собственную цепочку по той же логике.

2. Словарь автоматизации

Эти понятия нужны, чтобы студенты понимали не только интерфейс Albato, но и общую механику интеграций.

Источник данных

Место, где появляется новая информация. Это может быть форма, таблица, CRM, файл, письмо или сообщение. В нашем примере источник — Яндекс Форма.

Триггер

Событие, которое запускает сценарий. Например: пользователь отправил форму, в таблице появилась строка, пришло письмо. В нашем примере триггер — новая отправка Яндекс Формы.

Действие

Операция, которая выполняется после триггера. Например: отправить данные в GigaChat, отправить письмо, записать строку в таблицу. В одной связке может быть несколько действий.

Связка / сценарий

Цепочка из триггера и действий. Например: «форма отправлена → данные ушли в GigaChat → ответ отправлен на email».

Webhook

Специальная ссылка, на которую один сервис отправляет данные другому сервису. В нашем примере Яндекс Форма отправляет ответы на webhook Albato.

API

Способ, по которому сервисы общаются друг с другом. Один сервис отправляет запрос по правилам API, другой возвращает ответ. GigaChat API позволяет отправить prompt и получить ответ модели.

Ключ доступа / credential

Данные, которые подтверждают право подключаться к сервису: API-ключ, Authorization Key, SMTP-пароль приложения. Их нельзя показывать в скриншотах и публиковать.

Маппинг полей

Сопоставление: какое поле откуда взять и куда вставить. Например, поле data из формы попадает в prompt, а поле email — в получателя письма.

Prompt

Инструкция для ИИ. В автоматизации prompt обычно собирается из постоянного текста и переменных из формы или таблицы.

SMTP

Протокол отправки email. В нашей связке SMTP нужен, чтобы Albato мог отправить письмо через почтовый ящик Mail.ru.

Логи / история запусков

Журнал, где видно, какие шаги прошли успешно, а где возникла ошибка. Это первое место, куда нужно смотреть при отладке.

3. Что можно менять в этой схеме

Демонстрационная связка — только один пример. В домашней работе студент может заменить почти любой блок, если сохраняется логика: данные → автоматизация → ИИ → результат.

Блок схемы В нашем примере Что можно использовать вместо этого
Источник данных Яндекс Форма таблица, CSV-файл, анкета, CRM, заявка, письмо, выгрузка с сайта, ручной ввод
Автоматизация Albato Make, n8n, Google Apps Script, Python, другой интегратор или собственный код
ИИ GigaChat YandexGPT, Qwen, DeepSeek, Z.ai, локальная модель через Ollama, другой API
Результат Email таблица, чат, CRM, PDF/HTML-отчёт, уведомление, комментарий к заявке
Важно не количество сервисов, а понятная логика процесса. Маленький, но рабочий прототип лучше сложной схемы, которая не запускается.

4. Демонстрационный пример

Ниже описан пример, который можно показать на занятии: студент отправляет форму с таблицей и вопросом, GigaChat готовит аналитический комментарий, а Albato отправляет результат на email.

Яндекс Форма

Автоматизация
Albato
Ловит webhook и передаёт поля дальше.

GigaChat

1

Подготовьте Яндекс Форму

Форма собирает данные, которые потом будут переданы в автоматизацию.

В форме удобно создать такие поля:

Поле в форме Переменная в Albato Зачем нужно
Название набора данных dataname Чтобы в письме и prompt было понятно, о каких данных идёт речь.
Краткое описание данных datainfo Контекст для модели: что означают строки и столбцы.
Таблица или CSV data Основные данные, которые анализирует ИИ.
Что нужно узнать по данным? task Вопрос пользователя к данным.
Email для результата email Адрес, на который отправляется итоговое письмо.
Для первого прототипа лучше передавать таблицу как текст или CSV. Так данные проще подставить в prompt GigaChat.
Место для скриншота 1 Яндекс Форма в режиме редактирования: видны поля dataname, datainfo, data, task, email.
2

Передайте форму в Albato через webhook

Webhook — это адрес, куда Яндекс Форма отправляет ответы после заполнения.

  1. В Albato откройте Подключения и добавьте подключение Яндекс.Формы.
  2. Скопируйте webhook-ссылку, которую сгенерирует Albato.
  3. В Яндекс Форме откройте раздел Интеграция.
  4. Добавьте действие API / JSON-RPC.POST-запрос.
  5. Вставьте webhook-ссылку в поле URL.
  6. В блоке параметров создайте переменные dataname, datainfo, data, task, email и сопоставьте их с вопросами формы.
Если вы добавили новое поле в форму, нужно заново отправить тестовый ответ, чтобы Albato увидел это поле.
Место для скриншота 2 Albato: подключение Яндекс.Форм и webhook-ссылка.
Место для скриншота 3 Яндекс Форма: вкладка «Интеграция», JSON-RPC.POST и параметры формы.
3

Проверьте «ловец хуков»

На этом шаге Albato должен получить тестовые данные из формы.

  1. В Albato нажмите кнопку ожидания webhook или проверки входящих данных.
  2. Откройте Яндекс Форму как пользователь и отправьте тестовый ответ.
  3. Проверьте, что Albato показал поля dataname, datainfo, data, task, email.
Если Albato показывает поля формы, связка «Яндекс Форма → Albato» уже работает. Дальше можно добавлять GigaChat.
Место для скриншота 4 Albato: окно «Ловец хуков», сообщение «Данные получены», список полей формы.
4

Добавьте GigaChat как действие

GigaChat получает подготовленный prompt и возвращает аналитический комментарий.

  1. В Albato откройте Подключения и добавьте GigaChat.
  2. Вставьте Authorization Key и Scope из кабинета GigaChat API.
  3. В связке после триггера Яндекс Формы добавьте действие GigaChat.
  4. В prompt вставьте постоянный текст и переменные из формы: dataname, datainfo, data, task.
Authorization Key, Scope, SMTP-пароль и другие ключи доступа нельзя показывать в отчёте, на скриншотах и в общих материалах.

Пример логики prompt:

Ты выступаешь как осторожный аналитик данных. Название набора данных: [dataname] Описание данных: [datainfo] Таблица или CSV: [data] Вопрос пользователя: [task] Сделай короткий аналитический комментарий. Не делай причинных выводов без проверки. Не придумывай столбцы, которых нет в данных. Если данных мало, прямо скажи об этом.
В квадратных скобках показаны не обычные слова, а переменные из предыдущего шага. В интерфейсе Albato их нужно выбирать через кнопку добавления переменной.
Место для скриншота 5 Albato: подключение GigaChat. Ключи доступа замазать.
Место для скриншота 6 Albato: шаг GigaChat, prompt с переменными из Яндекс Формы.
5

Отправьте результат на email

Последнее действие фиксирует результат: отправляет письмо пользователю.

  1. После шага GigaChat добавьте действие Mail.ru / SMTP: отправить письмо.
  2. В поле От укажите email отправителя.
  3. В поле Кому подставьте переменную email из Яндекс Формы.
  4. В тему письма добавьте название набора данных: ИИ-анализ данных: [dataname].
  5. В текст письма вставьте данные из формы и ответ GigaChat.

Минимальный текст письма:

Здравствуйте! Ниже результат автоматического анализа данных через GigaChat. Название набора данных: [dataname] Описание данных: [datainfo] Вопрос пользователя: [task] Ответ GigaChat: [Ответ модели #1 → Ответ] --- Это учебный прототип: Яндекс Форма → Albato → GigaChat → Email.
После теста можно заменить обычный текст на HTML-шаблон письма. Для первого запуска важнее, чтобы цепочка стабильно работала.
Место для скриншота 7 Albato: шаг Mail.ru / SMTP. Видны поля «От», «Кому», «Тема», «Текст письма».
Место для скриншота 8 Полученное письмо с результатом GigaChat. Личные адреса можно замазать.
6

Проверьте запуск связки

Рабочая автоматизация должна проходить все шаги без ручного копирования ответа.

  1. Отправьте новую Яндекс Форму.
  2. Откройте историю запусков в Albato.
  3. Проверьте, что шаг Яндекс Формы получил поля.
  4. Проверьте, что GigaChat вернул ответ.
  5. Проверьте, что письмо ушло и пришло получателю.
Место для скриншота 9 Albato: история успешного запуска связки. Видно, что все шаги выполнены.

10. Идеи для собственного прототипа

Эти примеры помогают студентам увидеть ширину задачи. Не нужно копировать наш сценарий буквально.

Образовательный сценарий

Форма с вопросами студентов → ИИ группирует вопросы по темам → письмо преподавателю.

Опросный сценарий

Анкета обратной связи → ИИ выделяет частые проблемы → summary организатору.

Аналитический сценарий

CSV продаж или заявок → ИИ делает краткий аналитический комментарий → результат в письме или таблице.

Организационный сценарий

Форма регистрации на мероприятие → ИИ формирует сводку по участникам → письмо куратору.

Классификация обращений

Форма заявки → ИИ определяет категорию обращения и срочность → результат в таблицу или email.

Продвинутый сценарий

n8n или Python → API/локальная модель → отчёт. Подходит тем, кто хочет больше контроля и готов разбираться с настройкой.

11. Что должно быть в домашней работе

Свобода реализации сохраняется, но структура отчёта должна быть единой. Это защищает работу от «самотёка».

  1. Схема автоматизации: источник данных → триггер → действия → ИИ → результат.
  2. Источник данных: скриншот формы, таблицы, CSV, заявки или другого источника.
  3. Инструмент автоматизации: Albato, n8n, Make, Python или другой вариант.
  4. Prompt: текст, который передаётся в ИИ, с пояснением переменных.
  5. Пример входных данных: небольшой фрагмент данных, который обрабатывается.
  6. Пример результата: письмо, таблица, сообщение, отчёт или другой результат.
  7. Скрин успешного запуска: история выполнения или другой признак, что цепочка реально сработала.
  8. Ограничения: что ИИ может понять неправильно и что нужно проверять вручную.
Минимальный рекомендуемый путь: Яндекс Форма → Albato → GigaChat → Email. Но можно предложить свой путь, если он сохраняет общую логику.

12. Безопасность и типовые ошибки

Что нельзя делать

  • Показывать в отчёте API-ключи, Authorization Key, SMTP-пароль, токены и webhook-ссылки.
  • Передавать персональные, закрытые или чувствительные данные в учебные интеграции.
  • Считать ИИ-ответ готовой истиной без проверки чисел и исходных данных.

Частые ошибки

Проблема Что проверить
Albato не видит новое поле формы Поле нужно добавить в параметры Яндекс Формы и заново отправить тестовый ответ.
GigaChat отвечает слишком общо Уточнить prompt: попросить числа, ограничения, запретить причинные выводы без проверки.
Письмо не приходит Проверить email из формы, папку «Спам», историю запуска Albato и SMTP-подключение.
Ответ ИИ выглядит красиво, но сомнительно Проверить расчёты вручную: суммы, доли, пропуски, дубликаты, относительные показатели.
Хорошая автоматизация не отменяет ответственность человека. Она ускоряет процесс, но не гарантирует корректность вывода.
